# 案例：托盘清单初始化失败后无法恢复

日期：2026-10-28。适用范围：小笺的托盘、多窗口及本地版本部署维护。

## 原任务与预期

用户右键系统托盘图标后无法打开清单，主窗口显示“快捷清单暂时无法打开”。预期能查看任务、辨认完成状态并继续操作；清单故障不应使退出入口不可用。

## 已确认事实

1. 日志先记录清单窗口创建，随后出现 `runtime error: failed to receive message from webview`。
2. 后续右键重复访问同一失效窗口，没有创建新窗口，因而持续失败。
3. 当时运行的是 0.1.6，而此前放置的新文件及自启动目标是 0.1.7。文件交付和自启动修改未使正在运行的实例自动升级。
4. 现有日志不足以判断首次 WebView 初始化失败的底层诱因。启动参数不一致是以前修复过的问题，不能据此认定此次也是同一原因。

## 旧行为与认可的修正

| 旧行为 | 0.1.8 的修正 |
| --- | --- |
| 创建调用返回后立即缓存窗口 | 检查窗口可用性；失败清理活动句柄 |
| 后续一直复用失效的固定标签窗口 | 新建时使用新的 `quick-*` 标签，并调整 capability 范围 |
| 自定义清单失败时没有菜单可用 | 提供系统备用菜单：任务勾选、打开主窗口、退出 |
| 更新文件后未核对运行实例 | 确认旧进程路径，切换运行版本，核对自启动目标 |

实现入口：`src-tauri/src/tray.rs`、`src-tauri/capabilities/quick.json`、`src/app.js`。保留既有事务保存和 `tasks-changed` 同步机制，不重建任务数据库。

## 实际验证与边界

- 0.1.8 完成编译检查、发布构建、版本一致性检查和代码审查。
- 交付 exe 与桌面副本做了文件哈希核对；实际进程切换为 0.1.8，自启动目标同步更新，原数据库做了本地备份。
- 新日志记录 `quick window ready`、显示与焦点成功；用户确认“可以打开漂亮清单”。
- 本次没有新增或运行自动化回归测试；故障再次发生时的重建和系统备用菜单未实际触发验证，不能写成这些场景均已通过。
- 项目规则保存在仓库根目录 `AGENTS.md`。该文件按目录适用，案例仅在相关任务中读取；新聊天中的自动加载及行为迁移尚未实际验收。

## 后续验收方法（尚未执行）

在用户明确授权相关测试后，可在隔离环境模拟创建失败、重复右键、已缓存窗口失效及恢复成功；核对备用菜单完成/撤销/退出和保存失败提示，并确认主窗口与清单同步。部署时另查“旧进程仍运行、新文件已复制”的情况。

不要为了复现故障更改用户真实任务、破坏运行时或删除用户数据库，也不要把尚未执行的方案当作验证结果。
